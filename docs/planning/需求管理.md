## 2026-07-14 设计校准

状态：Done

结论：

- Policy 前对象统一命名为 `DecisionProposal`。
- Policy Gate 对每个 Proposal 记录 `PolicyEvaluation`。
- 只有 `APPROVED` 才签发 `DecisionTicket`。
- Signal State Machine 只消费 Policy 后的 DecisionTicket。
- Position 只影响 Policy、优先级和提醒语义，不改变市场结构信号的真假。
- 当前代码仍把 Policy 前对象实现为 `DecisionTicket`，必须在 REQ-0007 前完成契约迁移。
- Snapshot identity 必须绑定完整窗口；闭合 K 线必须满足时间真实性。
- Policy DEFERRED 必须允许在新上下文中追加评估，不能被幂等键永久阻塞。
- Ticket 必须绑定并验证 Signal 与业务上下文版本，状态机不能信任可任意构造的对象。
- 初始 Signal 不需要 Ticket；终态后使用新 generation，不重置旧实例。

### REQ-0009：第二轮地基不变量修正

状态：Done

目标：

- 修复第二轮审查已经通过现有代码复现的基础不变量问题。
- 在 Golden Case 和 PreFilter 前建立可信的 Snapshot 与 Signal 运行时输入。

范围：

- MarketSnapshot 使用完整有序窗口内容生成 snapshot_content_hash、snapshot_key 和 id。
- `is_closed=True` 强制 `received_at >= closed_at`。
- SignalInstance 初始 `latest_decision_ticket_id=None`，补 generation 和 setup_key 语义。
- 状态机迁移通过完整模型校验重建投影，明确 expires_at 冲突行为。
- 相同 Ticket ID 但 payload 不同必须抛出冲突。
- 更新对应契约测试、Provider 测试和状态机测试。

验收标准：

- `limit=2` 和 `limit=3` 的不同窗口不会得到相同 snapshot_id。
- 历史 K 线内容或闭合状态变化时 snapshot_content_hash 变化。
- received_at 早于 closed_at 的已闭合 K 线被拒绝。
- 状态迁移后不会出现 expires_at 早于 last_transition_at 的 SignalInstance。
- 初始 OBSERVING Signal 不需要伪造 DecisionTicket。
- 相同 Ticket ID 修改任一授权 payload 字段后被拒绝。
- 原有测试继续通过，并补齐上述回归测试。

交付：

- `MarketSnapshot.from_bars` 统一生成并校验 content hash、key 和稳定 UUID。
- `MarketBar` 与 `MarketSnapshot` 拒绝提前闭合和倒退的 as_of。
- `SignalInstance` 支持初始空 Ticket，并增加 generation/setup_key。
- `SignalStateMachine` 使用完整模型校验重建投影，拒绝过期或倒退时间。
- 内存幂等账本记录完整 Ticket payload 指纹，冲突 payload 不再作为重复消费。
- 新增 11 个回归测试，完整基线由 30 增至 41。

### REQ-0005：Crypto Candidate PreFilter 最小版本

状态：Planned

依赖：`REQ-0009` 已完成；先完成 `REQ-0006`。

目标：

- 从 `MarketSnapshot.latest_closed_bar` 生成第一条可复现 `CandidateEvent`。
- 先跑通确定性预筛选，不接 Agent，不接 LLM。
- 验证重复行情不会重复产生候选。

范围：

- 只处理 Crypto。
- 只使用已收盘 K 线。
- 优先支持一个简单、可解释的候选类型，例如 `STRUCTURE_BREAKOUT` 或
  `PRICE_ZONE_APPROACH`。
- 使用 `FakeCryptoProvider` 作为默认测试输入。

非目标：

- 不接真实交易提醒。
- 不接 Policy Gate。
- 不接 Agent 或 Skill Runtime。
- 不扩展 funding、OI、order book、ticker 等数据类型。

建议交付：

- `src/loot/domains/crypto/prefilter.py`
- `CryptoPreFilterInput` 或轻量方法参数，优先复用现有契约。
- 生成 `CandidateEvent` 的确定性规则。
- `tests/unit/domains/crypto/test_prefilter.py`
- `docs/architecture/market-domains/crypto-prefilter-v0.1.md`

验收标准：

- 无候选条件时返回空结果或明确的 no-candidate 结果。
- 满足条件时生成一个 `CandidateEvent`。
- `CandidateEvent.snapshot_id` 指向 `MarketSnapshot.id`。
- `dedupe_key` 对同一标的、周期、候选类型和 K 线稳定。
- 未收盘 K 线不能触发候选。
- 重复输入不会产生不同的 dedupe_key。
- 单元测试覆盖成功、无候选、未收盘过滤、重复输入。

### REQ-0006：Crypto Golden Case 最小集

状态：Planned

依赖：`REQ-0009` 已完成，Snapshot identity 已可可靠锁定输入窗口。

目标：

- 为第一条 Crypto 闭环准备可重复回放样例。
- 验证行情输入、候选生成和后续状态机消费的稳定性。

范围：

- 先用 FakeProvider 构造 2 到 3 个样例。
- 不引入真实历史行情归档。

建议 Golden Case：

1. 普通上涨但未触发候选。
2. 收盘突破阈值，生成 `STRUCTURE_BREAKOUT`。
3. 未收盘突破但收盘前回落，不生成候选。
4. 相同快照重复处理，候选 `dedupe_key` 稳定。

验收标准：

- Golden Case 输入可读、可复现。
- 每个样例有明确预期输出。
- 后续可被 replay 测试复用。
- Golden Case 先表达产品判断，不依赖已经实现的 PreFilter 反推预期。

### REQ-0007：Candidate 到 Signal 授权链路最小串联

状态：Planned

目标：

- 将 Fake Candidate 转成最小 `DecisionProposal`。
- 通过最小 Policy Gate 生成 `PolicyEvaluation`，批准时签发 `DecisionTicket`。
- 只允许 `DecisionTicket` 调用 Signal State Machine。
- 验证端到端幂等语义。

范围：

- 暂时不接 Agent。
- 使用 deterministic decision builder 生成 Proposal。
- 实现最小 Policy Gate，不引入完整 Guard 体系。
- 实现内存版 Signal 初始化入口和 generation 语义，持久化事务放在 REQ-0008。
- 只验证 `OBSERVING -> ARMED` 或 `ARMED -> TRIGGERED` 一条合法迁移。

验收标准：

- 同一 Candidate 重复消费不会产生重复 SignalEvent。
- 相同 Candidate 和规则版本产生稳定 Proposal dedupe_key。
- Policy 拒绝时不产生 DecisionTicket 和 SignalEvent。
- Policy DEFERRED 到期或上下文变化后可追加新评估，同一 evaluation_request 保持幂等。
- 同一 Proposal 整个生命周期最多签发一张 Ticket。
- Ticket 绑定 expected_signal_version 和业务 context_digest。
- 状态机从事实源适配器验证 APPROVED、proposal_digest 和上下文版本。
- 非法迁移被拒绝。
- 状态变化可追踪 `candidate_event_id`、`decision_proposal_id`、
  `policy_evaluation_id`、`decision_ticket_id` 和 `input_snapshot_id`。
