# Loot 上下文框架长期开发评审

## 1. 评审范围

- 新 Codex 是否能从仓库恢复当前状态和下一步。
- 动态事实、稳定架构、过程证据和需求状态是否职责清楚。
- 多设备环境是否可以复现验证。
- 文档规模增长后是否存在加载和漂移风险。
- 机械一致性是否具有自动检查。

## 2. 结论

当前框架可以支撑长期 vibe coding。经过本轮加固，动态事实已收敛到 memory/planning，
普通任务按需加载设计，macOS 环境可以通过仓库命令初始化，机械一致性由自动脚本检查。

框架定位仍是“Git 内轻量上下文层”，不引入外部知识库或复杂文档平台。

## 3. 已关闭问题

| 问题 | 处理 |
|---|---|
| 根 README 与 memory 状态冲突 | 根 README 删除动态需求状态，只链接权威入口 |
| 当前机器无法复现 41 测试 | `make setup` 安装依赖，`make check` 在 macOS 复验通过 |
| 每次强制加载完整系统架构 | AGENTS 改为按任务读取组件设计，系统文档只用于跨领域任务 |
| 链接扫描没有固定命令 | 新增 `scripts/check_context.py` 和 `make context-check` |
| memory 接近体量阈值 | 稳定规则改为链接，memory 保留当前事实和活跃差异 |
| Skill 多设备漂移 | 项目副本保持权威，validator 和哈希检查纳入自动流程 |

## 4. 保留风险

- 跨季度 carryover 规则尚未经历第一次真实季度切换。
- 自动检查能发现结构和链接问题，不能替代对状态、架构和实现语义的人工判断。
- 系统和组件设计继续增长时，仍需关注单次任务实际加载量，而不只看单文件行数。
